## 2. Решения с причинами (по каждому пакету)

### pi-ollama-cloud 0.12.1 → 0.13.1 — ВЗЯТЬ (срочно)
**Изменения** (релиз-ноуты полные): 0.12.2 — обновление каталога после списаний моделей Ollama от 2026-09-25 (`deepseek-v4-flash:0731`, `glm-5.1`, `qwen3.5:397b` удалены; рекомендованы `deepseek-v4.1-flash`, `glm-5.3`); 0.12.3 — индикатор использования, понятные ошибки сети, `OLLAMA_API_KEY` fallback; 0.13.0 — переход Ollama на новый API баланса `/api/balance` (квота, кредиты, даты обновления); 0.13.1 — исключение семейств Clef из каталога, фикс генерации цен, новый каталог моделей.
**Наши фиксы:** патчей нет. **Трудоёмкость:** S–M. **Целесообразность:** высокая — каталог и баланс задевают повседневную работу.
**Почему решение:** списание моделей уже случилось, а старый пакет перестанет показывать баланс — это не «новые фичи», а фактическая поломка наших рабочих путей.

### pi-subagents 0.79.1 → 0.88.0 — ВЗЯТЬ (планово)
**Изменения:** полные ноты только по 0.88.0 (0.79.2–0.87.0 — ноты в публичных источниках отсутствуют, NOT VERIFIED): обрезанный по лимиту вывод теперь ошибка, а не ложный успех; ребёнок в ожидании ответа не сжигает свой таймаут; прогресс ребёнка в виджете; чистка копий forked-сабов; `list` ≤30 + поиск; фиксы для Windows без PowerShell, выключенных MCP-серверов, шлюзов с prompt cache key.
**Наши фиксы:** патчей нет; но есть связка: `pi-polza` слушает RPC pi-subagents для учёта расходов подагентов — приёмка обязана её проверить.
**Трудоёмкость:** M (включая проверку связки). **Почему решение:** фиксы ровно наших сценариев (мы буквально видели класс дефекта «обрезанный вывод = ложный PASS» в своей работе); риск мал, польза прямая.

### rpiv-todo 2.12.0 → 2.15.0 — ВЗЯТЬ (планово)
**Изменения:** 15 мелких релизов; содержательный — 2.15.0: фикс краша при восстановлении сессии с битым снимком задач (маркерная строка обрезки чужого расширения восстанавливалась как задача и роняла оверлей). 2.13.0–2.14.2 — ноты пустые (NOT VERIFIED).
**Наши фиксы:** нет. **Трудоёмкость:** S. **Почему решение:** дешёвый фикс на нашем пути (восстановление сессий — повседневная операция).

### pi-goal-x 0.32.3 → 0.34.1 — ВЗЯТЬ (планово)
**Изменения** (полные тексты issues/PR — это списки изменений): 0.33.0 = #105 + #106 — обновление под Pi 1.4, idle pacing стал opt-in (`idleContinuationBackoff`), ручка `maxAutonomousRuns` как жёсткий стоп, обработка отмены старта, max thinking для auditor/Oracle; настраиваемые команды/клавиши/порядок пауз в `/goal-settings`. 0.34.0 = #107 — фиксы: устаревшие checkpoint'ы ставили паузу/списывали плату с новой цели; изменения промпта Pi переписывали кеш префикс; пустые аргументы задач вызывали повторы; атомарные записи переживают короткие Windows-блокировки. Требования: Pi 1.4+, Node 22.19+. 0.34.1 = #118 — фиксы четырёх жалоб на 0.34.0: уборка при переключении сессий, `update_goal` с пустыми полями, пропущенные задачи не блокируют завершение, горячие клавиши не перехватывают диалоги.
**Наши фиксы:** патчей нет; наши связки: порядок загрузки goal-x **до** intercom (workaround `turn_end`) — изменения его не задевают; настройки Goal X не меняем (новые опции opt-in).
**Трудоёмкость:** S–M. **Почему решение:** содержание выяснено и в нём — фиксы надёжности именно автономных запусков (stale checkpoints, плата с чужой цели — серьёзные баги); наши связки не задеты; требования совместимы с нашей сборкой. Проверка при приёмке: порядок загрузки и один headless-прогон.

### pi-intercom 0.17.1 → 0.18.1 — ВЗЯТЬ (планово, в паре с goal-x)
**Изменения** (полные ноты): 0.18.0 — честные статусы доставки («ждёт сессию» вместо «отправлено»), очередь сообщений не теряется при закрытии последней сессии, нечёткое совпадение имён сессий, клик по сообщению в fullscreen, handover работает с виртуальными моделями (роутерами). 0.18.1 — на Pi 1.2+ убрана лишняя строка «New intercom message above» в транскрипте при пробуждении; старые Pi без изменений.
**Наши фиксы:** патчей нет; косвенно задет наш workaround `turn_end` (область пробуждения/транскрипта) — проверить при приёмке.
**Трудоёмкость:** S–M. **Почему решение:** репозиторий найден (github.com/nicobailon/pi-intercom), ноты полные и честные, ломающего нет; обновлять логично в паре с goal-x — они связаны одной связкой, и проверка делается один раз.

### pi-cbm 1.2.1 → 2.0.0 + codebase-memory-mcp 0.11.0 → 0.12.1 — ОБСУДИТЬ (готовы к срезу, решение владельца)
**Изменения** (релиз-ноуты + анализ кода нового `client.ts`): клиент переписан — новая форма вызова `cli --json <tool>`, штатная передача `format:"json"`, модуль нормализации `normalize.js`, версионный gate (старый бинарь → ошибка). CBM CLI 0.12.0 (231 PR): документация (Markdown/PDF/ADR/OpenAPI) в графе, CBM Lens. 0.12.1: фиксы установок (лимит 256 MiB против бинаров 331 МБ), Helm-чарты в графе; ⚠ первый пере-индекс каждого проекта после апдейта — полная перестройка (image identities).
**Наши фиксы — судьба решена анализом кода:** патч `pi-cbm-011` (передача `format:"json"` + нормализация таблиц) **влит апстримом → при обновлении СНЯТЬ** (новый client.ts переписан, старые anchors не найдутся).
**Трудоёмкость:** L (пачка из двух пакетов, снятие патча, schema smoke, полный пере-индекс). **Целесообразность:** высокая — граф кода ежедневный инструмент, патч снимается, доки в графе — новая польза.
**Почему решение «обсудить»:** выгода и судьба патча ясны, но это мажор с полным пере-индексом и обязательной живой проверкой схемы (`cols/rows/groups` NOT VERIFIED — схема в нативном бинаре) — нужно согласие владельца на срез с приёмкой.

### pi-mcp-adapter 5.3.2 → 7.0.1 — КОПИТЬ (переносить отдельным срезом позже)
**Изменения** (полные ноты всех релизов): 5.4.0 — серверы видят проект (roots), `appendStructuredContent: false`, логи серверов в `mcp.log`, unattended worktrees. 6.0.0 — **Breaking: инструмент `mcpScript` УДАЛЁН** (заменён codemode-ом Pi), ключи `scriptMode`/`scriptSkill`/`settings.jev` мертвы, типы сломаны, новые фичи требуют Pi 0.99+. 7.0.0 — доработка MCP Tasks (задерживающие инструменты не блокируют сессию) и семантического поиска инструментов (базовая механика была уже в 5.3.2). 7.0.1 — имена инструментов >64 символов больше не ломают запросы к OpenAI-совместимым провайдерам (наш Polza-путь!), старт быстрее.
**Наши фиксы:** патчей нет; но **наша приёмка и привычки используют `mcpScript`** — переход требует перевода проверок на codemode (docs/components/mcp.md).
**Трудоёмкость:** L. **Почему решение:** стоимость перехода теперь известна точно и высока (переписывание приёмки + повторная проверка обоих транспортов WVM), а на текущей версии всё работает; торопиться некуда — копим до готовности к срезу.
