# MCP-инструменты для подагентов

Как дать подагентам (сабам) доступ к MCP-инструментам — и почему по умолчанию его нет.

## Главное правило

- Подагентам MCP-инструменты не выдаются сами. Наследования от основного агента нет.
- Каждый инструмент разрешается **явно**: имя прописывается в профиле подагента. Что не прописано — того нет.
- Сборка по умолчанию не разрешает подагентам ни одного MCP-инструмента. Это решение за пользователем: какие инструменты и кому выдать, решаете вы.

## Как это устроено

Две вещи должны совпасть.

**1. Явная прописка.** У профиля подагента есть полный список `tools:` — это не пожелание, а граница: чего в списке нет, того у подагента нет. MCP-инструменты добавляются в список селекторами:

- `mcp:имя-сервера/имя-инструмента` — один инструмент. Так и делайте: каждый инструмент — отдельной строкой.
- `mcp:имя-сервера` — разом все инструменты сервера. Удобно, но это уже пакетное разрешение.

**2. Фоновый запуск.** Подагент с MCP-инструментами запускается только фоном (в `pi-subagents` — `async: true`). Обычный запуск «вместе с основным агентом» отклоняется до старта с честной диагностикой. Это не дефект: в обычном запуске не поднимается адаптер MCP.

Имена серверов берутся из конфига адаптера `<PROFILE_DIR>/mcp-adapter.json`. Имена инструментов — как их отдаёт сервер: в namespace Pi инструмент выглядит как `mcp__сервер__инструмент`, дефисы в именах становятся подчёркиваниями.

## Как включить — по шагам

1. Создайте профиль подагента: `<PROFILE_DIR>/agents/<имя>.md`. Каталог пользовательский, обновления пакетов его не трогают.
2. Впишите в `tools:` обычные инструменты и нужные MCP-селекторы:

   ```yaml
   ---
   name: mcp-docs
   description: Помощник с явно разрешёнными инструментами Context7 и fetch
   tools: read, grep, find, ls, bash, write, mcp:context7/resolve-library-id, mcp:context7/query-docs, mcp:fetch/fetch
   thinking: high
   inheritProjectContext: true
   ---
   ```

   Тело файла ниже `---` — системный промпт подагента: кто он, что делает, чего не делает.
3. Подключите нужные MCP-серверы в конфиг адаптера — см. [MCP и необязательный HTTP auth](components/mcp.md). После подключения **нового** сервера перезапустите Pi: адаптер запоминает список инструментов при старте, и без перезапуска селектор на новый сервер не разрешится.
4. Запустите подагента фоном. Если селектор написан с ошибкой или сервер не из конфига, запуск отклонится до старта и перечислит неразрешённые имена — читайте список и правьте профиль.
5. Проверьте короткой пробой (см. ниже).

## Проверка

Дайте подагенту задачу: «перечислить свои `mcp__`-инструменты и сделать по одному пробному read-only вызову на каждый разрешённый сервер». В задании укажите бюджет tool-call и запрет на `confirm=True`. Хороший отчёт — таблица: сервер | инструменты видны | вызов удался | текст ошибки дословно.

Живой пример (проверено 2026-11-18): в профиле разрешены `mcp:context7` и `mcp:fetch` → подагент увидел три инструмента (`context7_resolve-library-id`, `context7_query-docs`, `fetch_fetch`), оба пробных вызова прошли.

## Когда разрешение не сработает

- инструмент скрыт в конфиге сервера (`hidden`) — выдать его нельзя никому;
- у сервера задан `includeTools`/`excludeTools` — ограничения действуют и на подагентов;
- сервер отключён (`disabled`) — молча пропускается;
- сервер добавлен кодом «на лету» и не записан в конфиг адаптера — детям он недоступен, запуск отклоняется с `Unresolved MCP direct-tool selectors`;
- опечатка в имени сервера или инструмента — запуск отклоняется до старта;
- запуск не фоновой — нужен `async: true`;
- новый сервер подключён без перезапуска Pi — селектор не разрешится до перезапуска.

## Общий инструмент `mcp` — это не явная прописка

Если в `tools:` указать общий инструмент `mcp`, подагент получает доступ ко **всем** серверам адаптера разом. Это грубый ключ «всё или ничего». Сборка им не пользуется и не рекомендует: перечисляйте инструменты явно.

## Позиция сборки

Сборка не разрешает подагентам MCP-инструменты за пользователя и не содержит готовых профилей с MCP-доступом. Включение — ручное, по шагам выше. Ответственность за выбор инструментов — на пользователе: один разрешённый инструмент — одно явное имя в профиле.
