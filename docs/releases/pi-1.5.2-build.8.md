## Установка: опыт этого среза

`install.ps1 -Apply` остановился с `EBUSY` на `pi-tui\native\win32\prebuilds\win32-x64\win32-platform.node` — файл держат запущенные процессы Pi (Windows не отдаёт загруженные нативные модули). Прерванная npm-установка ядра оставила неполный вложенный пакет `openai` (пустой подкаталог `turns/`), из-за чего новые процессы субагентов падали с «Cannot find module … turns.mjs». Восстановление: точечный `npm install openai@7.19.0 --no-save` внутри каталога ядра (при живых процессах это работает — в `openai` нет загруженных нативных модулей); пакеты профилей затем поставлены штатным `pi install` exact-sources (10/10, оба профиля).

## Известные ограничения

1. **Полная переустановка ядра** (`npm install -g @earendil-works/pi-coding-agent@1.5.2`) невозможна при работающих процессах Pi — требуется закрытые окна. В этом срезе ядро не переустанавливалось (та же версия 1.5.2), вложенный `openai` восстановлен точечно. Рекомендуется один полный Apply при закрытых Pi.
2. **Неполное обновление каталога ollama-cloud** (болезнь пакета, описана в его README: «обновление бывает неполным — повторите позже»): профиль Task этого ПК сохраняет старый набор моделей (со списанными `0731`/`glm-5.1`) и не показывает `:1017`, хотя Code-профиль показывает. Лечение: `pi update --models`, повторить позже. На свежей установке каталог обновляется при первом старте; сама модель доказана живым ответом.
3. **D.5 — частично** (активная Goal-часть TUI), **D.7 — NOT TESTED** (TUI): требуют интерактивного интерфейса.
4. **Проверочная обвязка навыка** (21 проверка) написана под прежние скрипты навыка: 5/21 проходит. Приведение обвязки к новым скриптам — отдельным срезом.
5. **Прочие остатки** (не горят): ротация ключа Polza (руками владельца, процедура — `docs/polza-memory.md`), 8 падений `npm test` pi-polza (нужна dev-зависимость), teardown-крестик профиля роли `researcher` у субагентов.
