# Pi 1.4.0 build.5 — pi-polza 0.3.0: доступный каталог, работающий импорт подагентов, уровни из каталога

Дата: 2026-10-30. Выпуск после [build.4](pi-1.4.0-build.4.md). Формат тега: `pi-v1.4.0-build.5`.
Ядро не менялось: Pi 1.4.0, Node 25.8.1, npm 11.11.0, Session Search 1.6.0, Memory 1.6.1.
Единственное изменение состава — `pi-polza` **0.2.2 → 0.3.0**, закреплённый опубликованным
commit `377b4e6142ae943d7eaf2d33e166139217cae543` (release `v0.3.0`, annotated tag object
`1e8fc7674e54171df5cd7342fb03b3dce60fe4db`) в manifest и обоих профильных templates.

## Что изменилось для пользователя

- **Модели больше не исчезают из-за отсутствующей цифры.** Неизвестный предел ответа не скрывает
  модель: значение берётся у Polza, затем из справочника, а если его нет нигде — ограничивается
  размером контекста. На реальном снимке каталога предлагалось 274 модели из 300, теперь **298**;
  `anthropic/claude-sonnet-5.5` и `anthropic/claude-opus-5.5` присутствуют без обогащения.
- **Уровни рассуждений `xhigh`/`max`** появляются там, где каталог их заявляет: опубликованный
  `supported_efforts` есть у 85 из 300 чат-моделей, `xhigh` заявлен у 44, `reasoning_effort`
  объявлен у 187. Отсутствующие в списке уровни скрываются, а не угадываются. Влияние уровня на
  живой ответ не проверялось — метки `not verified` сохранены.
- **Импорт расходов фоновых подагентов включается.** Ответ `pi-subagents` читается из версионного
  конверта (`data.events`); раньше мост не активировался ни разу. `/polza-cost` показывает
  состояние импорта отдельной строкой и не заявляет `complete`, когда фоновый учёт отсутствует.
- **Полученная цена сохраняется при обрыве ответа** (запрос был оплачен), а причина терминала
  попадает в аномалию вместо стирания суммы.
- **Справочник метаданных** читается как свежайшая копия из проекта или общей
  `<home>/.pi/pi-polza-cache`, запись идёт в общую — папка запуска больше не решает, полон ли список.
- `/polza-refresh` сообщает, сколько моделей предложено, сколько доступно и кого отбросили с причиной.

## Рабочая установка (оба профиля)

Штатный `pi install` из опубликованного commit, отдельно для Code и Task:

- Code: `~/.pi/agent/settings.json` содержит пин `…pi-polza@377b4e6…`; install clone стоит на
  `377b4e6 chore(release): 0.3.0`; `package.json` — `0.3.0`.
- Task: тот же пин в `~/.pi/task/settings.json`, установка подтверждена.
- `pi --list-models` для Code: **298 строк провайдера `polza`**, включая `anthropic/claude-sonnet-5.5`
  и `anthropic/claude-opus-5.5`.
- Карта уровней проверена на установленной копии напрямую: список `[low, high, xhigh]` даёт
  `low/high/xhigh` и скрывает остальные; объявленный `reasoning_effort` без списка пропускает имена
  уровней и скрывает `off`; у модели без reasoning карты нет.

## Известные ограничения

- Живой прогон `xhigh`/`max` не выполнялся ни на одной модели: уровень может быть отклонён
  провайдером — это отказ запроса, а не тихая подмена поведения.
- Полный живой цикл «фоновый подагент → завершение → запись в родительскую сессию» инструментально
  не прогонялся; работающий импорт подтверждён владельцем на его установке, а не лабораторным тестом.
- Устаревший общий кэш справочника даёт другой состав моделей при том же числе: проверяйте
  конкретные модели, а не количество строк.
- Memory, Session Search, их индексы, auth, Goal X и пользовательские данные этим выпуском не менялись.
