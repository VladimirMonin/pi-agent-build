# Pi 1.4.0 build.6 — pi-polza 0.3.1 и приведённое к конвенции оформление выпусков

Дата: 2026-10-30. Выпуск после [build.5](pi-1.4.0-build.5.md). Формат тега: `pi-v1.4.0-build.6`.
Ядро не менялось: Pi 1.4.0, Node 25.8.1, npm 11.11.0, Session Search 1.6.0, Memory 1.6.1.
Единственное изменение состава — `pi-polza` **0.3.0 → 0.3.1**, закреплённый опубликованным
commit `878fd144fd7eebe12b34342a8eb21a2cb8b143c9` (release `v0.3.1`, annotated tag object
`a9dc20ef831a425cd0ab2e26f3a6981fb62e1691`) в manifest и обоих профильных templates.

## Что изменилось

- **Исправлен пример установки в README провайдера.** Он ставил `v0.2.2`, то есть версию без
  исправлений каталога и учёта — по документации пользователь получал старое поведение. Теперь
  пример закреплён на текущем выпуске. Код провайдера между 0.3.0 и 0.3.1 идентичен.
- **Оформление релизов приведено к принятому виду.** Заголовок и тело GitHub Release начинаются
  с одной строки-питча, далее скриншот, разделы возможностей, установки, проверок, ограничений и
  лицензии. Это применено к `pi-polza` 0.3.0 и 0.3.1 и к заметке этой сборки.

## Проверки

- `npm test` в `pi-polza`: **225 тестов, 170 прошли, 8 падений, 47 пропущено**. Все восемь падений —
  `tests/startup-native.test.ts`, предсуществующее внешнее условие: в checkout нет установленного
  `@earendil-works/pi-coding-agent`.
- Пакет 0.3.1: `npm pack --dry-run` — 45 файлов, состав runtime-файлов тот же, что в 0.3.0.
- Оба профиля переустановлены из опубликованного commit; в установленных клонах `HEAD` = `878fd14`,
  тег `refs/tags/v0.3.1` = `a9dc20e`, отслеживаемых изменений нет, `package.json` — `0.3.1`.
- `verify.ps1 -Profile Both`: **failures=0 warnings=0** (пакеты, теги, патчи, внешние инструменты).
- `pi --list-models` для Code: **298 строк провайдера `polza`**, включая `anthropic/claude-sonnet-5.5`
  и `anthropic/claude-opus-5.5`.
- `safety-check.ps1 -Scope Both`: PASS, 499 файлов, замечаний нет.
- Платных запросов к моделям не выполнялось.

## Известные ограничения

- Живой прогон `xhigh`/`max` не выполнялся; отказ провайдера на неподдерживаемом уровне возможен.
- Полный живой цикл фонового подагента инструментально не прогонялся: подтверждение владельца,
  а не лабораторный тест.
- `pi install` скачивает коммит, но не теги: после установки тег `v0.3.1` подтянут отдельно
  (`git fetch origin tag v0.3.1`), иначе проверка сборки честно сообщает о расхождении metadata.
  Установщик пока этого шага не делает.

## Откат

Вернуть пин `pi-polza` на `e91b09504f7a445b477eaab77cc02d1db067a1e7` (`v0.2.2`) в manifest и
обоих templates, установить эту ревизию в обоих профилях и перезапустить Pi. Опубликованные теги
не двигаются; исправление — новый выпуск.
