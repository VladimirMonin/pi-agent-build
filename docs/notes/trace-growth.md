# Рост файлов трассировки

## Наблюдение

`pi-trace-extension` пишет `events.jsonl` на сессию и не ограничивает его размер. На одной длинной оркестраторской сессии файл вырос до **144 МБ** за несколько часов; весь каталог `traces/` занял **222 МБ** за один день работы.

Разбивка по типам событий для той сессии:

| Тип события | Кол-во | Объём | Доля |
|---|---|---|---|
| `llm_request` | 216 | 141.6 MB | **99%** |
| `tool_end` | 358 | 0.4 MB | <1% |
| `step_end` | 215 | 0.4 MB | <1% |
| `tool_start` | 358 | 0.3 MB | <1% |
| остальные | ~700 | <0.1 MB | <1% |

Внутри `llm_request`: min 79 KB, median 631 KB, max 1.36 MB на событие.

## Причина

Событие `llm_request` сохраняет **весь payload запроса к модели**, включая полный массив `messages`. Каждый ход отправляет всю историю диалога, поэтому одно и то же содержимое переписывается в файл на каждом шаге. При `N` ходов и растущем контексте объём растёт **квадратично** от длины сессии.

`TRUNCATE_STR = 8000` (`extensions/trace/index.ts`) обрезает **каждую отдельную строку**, но не ограничивает число сообщений и не дедуплицирует историю. Поэтому длинная сессия с большим контекстом даёт сотни мегабайт даже при работающей обрезке.

Дополнительно: подкаталог `traces/session/` агрегирует события subagent-ранов (в наблюдении — 27 запусков) и использует литеральный `sessionId: "session"`, из-за чего все раны попадают в один файл.

## Последствия

- `trace.html` рендерится из того же файла; при десятках мегабайт рендер замедляется, а сам HTML сопоставим по размеру с `events.jsonl` (в наблюдении — 32 МБ).
- Каталог `traces/` растёт без верхней границы и не чистится автоматически.
- Трейс содержит prompts, ответы модели и результаты инструментов, поэтому крупные файлы — ещё и носитель чувствительных данных.

## Что делать

Автоматической ротации в upstream нет — это заявлено в README пакета и остаётся открытым пунктом roadmap. Варианты:

1. **Периодически удалять старые трейсы** вручную: `traces/<session-id>/` и `traces/session/` можно удалять целиком, они не влияют на работу Pi и не являются источником для session-search или памяти.
2. **Начинать новую сессию** для длинной работы — размер `events.jsonl` привязан к сессии.
3. **Отключить пакет**, если трейс не нужен: убрать `npm:pi-trace-extension` из `packages` в `settings.json` профиля либо перевести запись в объектную форму с пустым набором расширений (как `pi-background-tasks` в шаблонах сборки):

   ```json
   { "source": "npm:pi-trace-extension@0.1.16", "extensions": [] }
   ```

   Пакет останется установленным, но его extension не загрузится, и новые трейсы писаться не будут. Существующие каталоги `traces/` нужно удалить отдельно.

## Оговорка

Локальный patch `trace-ru-windows-profile` русифицирует UI и разводит пути Code/Task, но **не** добавляет ротацию — это отдельная функциональность, которой в upstream пока нет. Если ротация понадобится, её придётся реализовывать как самостоятельное изменение extension.
