# Memory Ops

> АГЕНТ: прочитай этот файл целиком. Перед любой операцией открой [общие правила](instructions/00-shared-rules.md).

## Назначение

Навык обслуживает факты `semantic` и уроки `lessons` в SQLite-хранилище памяти: измеряет реальную стоимость инъекции, проводит аудит, предлагает безопасные преобразования и применяет подтверждённые планы.

Главный принцип: **одна запись — одна тема; ценность равна стоимости повторного открытия; ни один факт не теряется**.

## Жёсткие правила

1. Сначала измеряй достижимость и бюджет, затем оценивай стиль записей.
2. Никаких удалений, сжатий и слияний без явного согласия владельца.
3. `source=user` нельзя удалять, переименовывать или переписывать без отдельного owner override. При разрешённой переработке сохрани `source=user`.
4. Безопасный порядок: создать замену → проверить → удалить старое.
5. Все утверждения о путях, версиях и файлах проверяй инструментами.
6. Не сохраняй секреты, имя владельца и одноразовое состояние задачи. В отчётах секреты только редактируются: `sk-<REDACTED>`.
7. Пользовательский ответ — на языке пользователя; файлы этой редакции — на русском.
8. Любой mutating script работает как dry-run без `--apply`: анализирует стабильную временную byte-копию `db` + WAL и не открывает исходную SQLite даже read-only. Исходные `db`/`-wal`/`-shm` остаются byte-identical.
9. Путь к БД всегда передаётся явно через `--db`; значения, зависящего от пользователя или машины, нет.
10. При apply target сначала захватывается `BEGIN IMMEDIATE`; plan, source state, preservation, scope и owner guards полностью повторяются внутри транзакции. Missing/stale/malformed plan отклоняется целиком, partial apply запрещён.
11. `inject-probe.mjs` делает только консервативную структурную оценку на временном SQLite snapshot. Он не импортирует и не исполняет код установленного или произвольного plugin.
12. Protected identifiers, paths, flags, versions и числа сохраняются byte-exact. Значимые слова и все односимвольные лексемы каждого source обязаны остаться в исходном регистре и порядке, включая отрицание; guard нельзя отключить. Изменённый fact value/key получает `embedding=NULL`.

## Модель хранилища

| Хранилище | Адрес | Особенности |
|---|---|---|
| `semantic` | dotted `key` | релевантные факты и co-expansion домена |
| `lessons` | UUID `id` | активные строки `is_deleted=0`, обычно до 50 |
| `events` | внутренний id | не инъецируется; в операции навыка не входит |

Факт содержит `confidence`, `source`, даты и embedding. Урок содержит `category`, `source`, `negative`, `project`, `created_at`, `is_deleted`. Наблюдаемая схема и версия плагина важнее документации: при расхождении фиксируй допущение.

### Стоимость инъекции

- Ключ из 3+ сегментов (`a.b.c`) может подтянуть соседей по префиксу `a.b`.
- Ключ из 2 сегментов (`pref.editor`) — leaf и не расширяет домен.
- Уроки выбираются по `project=<slug cwd> OR project IS NULL`.
- Лимит блока зависит от установленного плагина; известное значение 8000 символов нельзя считать вечной константой.
- Недостижимая запись не расходует бюджет. Не оптимизируй её ради косметики.

## Перед любой операцией

1. Прочитай [общие правила](instructions/00-shared-rules.md).
2. Получи явный путь к БД; не угадывай домашний каталог.
3. Запусти консервативную структурную оценку: `node scripts/inject-probe.mjs --db=<path> --estimate`; скрипт сам создаст стабильный snapshot, включая активный WAL, и не исполняет код plugin.
4. Выбери режим, пройди его Gate и сначала покажи предложение.
5. Для записи: запусти clean dry-run, покажи точный план, получи подтверждение, сделай проверенный внешний recovery backup, затем добавь `--apply`.
7. Если затрагивается `source=user`, дополнительно требуется `--owner-override` после явного согласия владельца.
8. Проверь результат чтением из точной БД и повторным probe на копии.

## Скрипты

Подробные команды и гарантии: [scripts/README.md](scripts/README.md).

- `inject-probe.mjs` — консервативная структурная оценка только на временной копии; plugin-код не исполняется.
- `apply-facts.mjs` — применение merge-блоков фактов.
- `apply-lessons.mjs` — применение merge-блоков уроков с token coverage.
- `patch-entries.mjs` — точечные сокращения и переименования.

Проверка реального инжектора, historical дефект1.5 и текущий patch1.6 описаны отдельно:
в репозиторном `docs/fixes/memory-injection.md`. Публичный
`inject-probe.mjs` выполняет лишь структурную оценку, не выдавай её за
результат настоящей инъекции. Не устанавливай поверх репозиторного patcher
параллельный локальный patcher, не сверив байты и оба профиля.

## Журналы

Реальные журналы не входят в публичный пакет. Создавай локальные файлы в игнорируемом `runtime/` по [шаблону работы](templates/work-log.example.md) и [шаблону дефекта](templates/defect-log.example.md). Не записывай тексты памяти, секреты или персональные данные — только дату, режим, идентификаторы и счётчики.

## Критерий готовности операции

- [ ] Достижимость и бюджет измерены на копии.
- [ ] Удалённые строки исключены из подсчёта.
- [ ] Каждое предложение подтверждено доказательством.
- [ ] Есть явное согласие на мутацию; для `source=user` есть отдельный owner override.
- [ ] Dry-run не создал и не изменил файлов.
- [ ] Hash/size исходных `db`, `-wal`, `-shm` до apply не изменились.
- [ ] Backup создан вне навыка.
- [ ] После apply результат прочитан обратно и факты сверены N/N.
- [ ] Ни одна группа не была пропущена; весь подтверждённый plan применён или целиком отклонён.
- [ ] Runtime-журнал не содержит содержимого записей.
