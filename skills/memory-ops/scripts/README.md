# scripts/ — рабочие инструменты pi-memory-ops

Все скрипты на Node (≥ 22, встроенный `node:sqlite`) и **переносимы**: Windows и
macOS, ни одного абсолютного пути конкретной машины. Порядок разрешения путей —
везде одинаковый: аргумент командной строки → переменная окружения → домашняя
папка.

| Что нужно | Откуда берётся |
|---|---|
| база памяти | `--db=<path>` → `PI_MEMORY_DB` → `<home>/.pi/memory/memory.db` |
| settings.json профиля | `--settings=<path>` → `PI_CODING_AGENT_DIR/settings.json` → `<home>/.pi/agent/settings.json` |
| сборщик плагина | `--bundle=<path>` → `PI_MEMORY_BUNDLE` → `<home>/.pi/agent/npm/node_modules/@samfp/pi-memory/dist/index.js` |

Скрипты **изменения** по умолчанию работают в режиме dry-run и меняют БД
только с явным `--apply`. Пробники вызывают сборщик, который обновляет
`last_accessed`/эмбеддинги — поэтому они запускаются **только по копии**;
живой `memory.db` отклоняется guard'ом (`inject-probe`, `check-injector`).
Ни один скрипт не удаляет 💀-группы и не трогает записи `source=user` — это
решение владельца, вручную.

## Обязательный порядок перед любой мутацией

```bash
node scripts/db-copy.mjs "<live.db>" "<backup>/memory-$(date +%Y%m%d-%H%M).db"
```

Бэкап — не формальность: именно он позволил восстановить 210 уроков после
ошибки в применителе (см. историю в `references/changelog.md`, 2026-09-24).

## Что внутри

| файл | назначение |
|---|---|
| `db-copy.mjs` | консистентная копия базы (`VACUUM INTO`), работает без CLI `sqlite3` (на Windows его часто нет). Основа для бэкапов и всех проб. |
| `inject-probe.mjs` | **измеряет настоящий инжектируемый блок** — вызывает сборщик для cwd/промптов. Требует `--db=<копия>`. `--settings` задаёт профиль: его `memory`-конфиг (`factProjectAliases`, `lessonInjection`) передаётся в сборщик целиком — без конфига проектные факты молча отфильтровываются и замер врёт. `--lesson-injection=all\|selective` переопределяет режим; `--estimate` — грубая SQL-модель (потенциальная стоимость, **не** нижняя граница блока). |
| `export-lanes.mjs` | read-only выгрузка дизжойнтных срезов для массовой работы (🧱): факты — по 2-сегментному домену, уроки — по `project`; баланс по символам; по файлу UTF-8 на полку. Полки работают с файлами, не с БД. |
| `validate-apply.mjs` | пред-применяемая валидация **всех планов прогона одним вызовом** (кросс-плановые пересечения ловятся только так): формат, существование ключей/uuid, **запрет user-записей в удалении**, пересечения блоков/полок, длина значений, backticks в ПРОЕКТ, «ЖДЁТ»-блоки в применяемых секциях. `node validate-apply.mjs --db=<db> <plan1.md> <plan2.md> …` |
| `normalize-apply.mjs` | точечная правка планов перед применением: снимает backticks в `ПРОЕКТ:`, переносит блоки «ЖДЁТ/⚠️» в «Ждёт подтверждения». `node normalize-apply.mjs <plan.md…>` |
| `apply-facts.mjs` | применяет раздел **«Группы слияния фактов»** плана: upsert слитого значения в KEEP-ключ, затем удаление поглощённых. Понимает ключи в backticks и без, пропускает 💀-группы, печатает не затронутые записи. Dry-run по умолчанию. |
| `apply-lessons.mjs` | применяет раздел **«Слияние уроков»**: вставляет слитый урок с новым id, удаляет поглощённые (мягко, `is_deleted=1`); сохраняет `project` (из плана или большинством), **fail-closed** проверка сохранности токенов. Dry-run по умолчанию. |
| `patch-entries.mjs` | точечные правки по JSON: `renames` (перенос ключей), `facts` (новый текст по ключу), `lessons` (новый текст по id — **на месте**, id/project/source/negative сохраняются). |
| `check-injector.mjs` | поведенческая регрессия на **копии**: целостность блока (≤8000, без усечения, строки целые), покрытие project-тегов (локальные уроки каждого проекта появляются). `--cases=<json>` добавляет свои present/absent-проверки (например, на утечку чужого проекта). |

**Применение — строго последовательно, один план за раз** (база одна, второй
писатель получает `SQLITE_BUSY`): normalize → validate по всем планам → «да»
владельца на удаления → бэкап → dry-run → `--apply`. Параллельные применители
запрещены.

**Молчание запрещено (с 1.0.0).** Валидатор и оба применителя помечают
нераспознанный `###`-блок как нарушение/проблему: раньше блоки в неофициальном
диалекте (например `НОВОЕ:` вместо `НОВОЕ ЗНАЧЕНИЕ:`) молча выпадали из
прогона. Единый диалект с образцом — `references/lane-contract.md`.

## Проверка сохранности токенов (apply-lessons)

Из текстов поглощённых уроков извлекаются «субстанции» — snake_case,
camelCase, КОНСТАНТЫ, числа, пути, строки в backticks. Если объединение этих
токенов не покрыто слитым текстом (по умолчанию < 0.9 и токенов ≥ 3), группа
**не применяется**: fail-closed, а не «поверим полке». Метрика неприменима к
чисто прозаическим урокам (мало токенов) — такие группы применяются, но
печатаются отдельно.

## Самопроверка внутри транзакции

`apply-lessons.mjs` после вставки проверяет, что каждая новая строка реально
существует, и откатывает транзакцию иначе. Это не паранойя: 2026-09-24 одна
правка скрипта поместила вызов вставки внутрь комментария, и серия удалений
прошла без замен. Любая правка применителя требует повторного dry-run.

## Локальный runtime-патч (необязательно, привязан к сборке)

Если ваша сборка Pi несёт локальный scoped-injection патч плагина памяти
(фильтрация проектного скоупа, квоты секций вместо усечения, hybrid recall),
его источник и проверка живут в **отдельном репозитории патча**, не в этом
навыке. Патч привязан к конкретной версии `@samfp/pi-memory` (проверено на
**1.6.1**, 2026-11-11; константы и якоря — version-bound):

```bash
python <PATCH_DIR>/apply.py --agent-dir=<PROFILE> --check   # sha + RUNTIME-SAFE
python <PATCH_DIR>/apply.py --agent-dir=<PROFILE>           # применить
node scripts/check-injector.mjs --db=<копия.db>             # регрессия на копии
```

Любой `pi update` возвращает stock-бандл — **после обновления пакета
переприменяй патч** и перезапускай Pi. Фича живёт только в собранном
`dist/index.js`, поэтому `npm run build` без повторного применения её снесёт.

## inject-probe: шим зависимостей

`dist/` плагина импортирует `@sinclair/typebox`, которого в
`<npm-root>/node_modules` может не быть (у плагина — пустой каталог-призрак).
Если пробник падает с `ERR_MODULE_NOT_FOUND`, создай разовый шим (обратимо,
перезаписывается `pi update`) из vendored-копии внутри pi-coding-agent:

```bash
N="<npm-root>/node_modules"          # например <home>/.pi/agent/npm/node_modules
TB="<pi-coding-agent>/node_modules/typebox"
mkdir -p "$N/@sinclair" && cp -r "$TB" "$N/@sinclair/typebox"
```

Ограничение: это обычно `typebox@1.x`, тогда как плагин объявляет peer
`@sinclair/typebox: *` — используемый экспорт `Type` работает, но шим тенит
резолв до явной установки правильной версии.
