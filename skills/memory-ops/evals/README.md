# Evaluation pack

> АГЕНТ: ЧИТАЙ ЭТОТ ФАЙЛ ЦЕЛИКОМ при проверке релизной готовности навыка.

## Фразы срабатывания

Позитивные:
- «Проведи аудит моей постоянной памяти».
- «Сожми дубли в lessons, но сначала покажи план».
- «Проверь drift записей consolidation».
- «Примени merge-план к SQLite безопасно».

Негативные:
- «Запомни прогресс текущего запуска до следующего сообщения» — временное состояние.
- «Оптимизируй SQL-запрос приложения» — не обслуживание памяти.

Пограничные:
- «Запомни эту настройку навсегда» — режим новой записи только после fitness filter.
- «Удалить старые заметки» — сначала выяснить, относится ли запрос к memory store.

## Smoke scenarios

1. Dry-run facts: exit 0; hash БД неизменен; новых файлов нет; вывод содержит `DRY-RUN`.
2. Owner guard: apply без override отклонён; строка `source=user` жива; с отдельным override операция проходит и provenance сохраняется.
3. Probe: structural estimate включает leaf values, явно не моделирует prompt reachability, исходная fixture остаётся byte-identical, временная копия удаляется.
4. Public hygiene: нет персональных абсолютных путей; все Markdown-ссылки существуют; report samples помечены как синтетические.

## Качественный обзор

- Агент сначала измеряет бюджет, а не предлагает косметику.
- Различает proposal, dry-run и apply.
- Не превращает `--owner-override` в автоматический флаг.
- Финальный отчёт содержит проверенный результат и нерешённые риски.

## Регрессии

Автоматический набор: `tests/memory-ops/security.test.mjs`. После изменения процедуры прогоняются все тесты, а не один свежий кейс.

Stop criterion: все automated assertions зелёные, ссылки валидны, в пакете нет runtime-данных, и повторный обзор не находит обхода owner guard.
