# Режим ⚡ Быстрый обзор

> АГЕНТ: ЧИТАЙ ЭТОТ ФАЙЛ ЦЕЛИКОМ. Режим не делает мутаций и не выдаёт slice за полный store.

Когда: короткая оценка в начале/середине сессии. Формат: [synthetic quick scan](../reports/report-quick-scan.md).

## Шаги

1. Прочитать текущий `<memory>` block без глубокого обхода БД. Если блока нет, явно сказать, что quick scan невозможен без входных данных.
2. Помнить, что блок — relevance slice и может быть усечён. Отсутствие записи не доказывает ненужность или недостижимость.
3. Приблизительно посчитать флаги: 💀, 🕰️, 🌀, 🔁, 🧬. Отдельно отметить явный truncation marker.
4. Дать 1–3 предложения: размер видимого slice, счётчики флагов, ограничение оценки.
5. При флагах предложить полный аудит или конкретный режим. Не начинать изменения.

## Gate

- [ ] Анализируется slice, а не заявляется полный аудит.
- [ ] Видимый truncation назван.
- [ ] Счётчики содержат все пять флагов.
- [ ] Нет таблицы и длинного отчёта.
- [ ] Нет записи в БД или runtime.
- [ ] При проблемах предложен следующий read-only шаг.
