# Режим 🌀→✅ Разделение смеси

> АГЕНТ: ЧИТАЙ ЭТОТ ФАЙЛ ЦЕЛИКОМ. Разделение не должно терять факты и не должно механически дробить единый сюжет.

Когда: одна запись содержит независимые темы. План: [synthetic regroup plan](../reports/report-regroup-plan.md).

## Шаги

1. Выписать все утверждения источника и применить deletion test.
2. Применить «один сюжет»: части одного процесса остаются вместе, даже если предложение можно удалить грамматически.
3. Для каждой отделяемой темы выбрать destination: существующая запись, новая запись или другой store только при явном обосновании.
4. Составить все target drafts сразу. Сверить source → targets факт за фактом, N/N.
5. Показать `было → станет`, точные ключи/ids, количество create/update/delete и reachability impact.
6. Для каждого `source=user` показать полный old → new и отдельно запросить owner override.
7. После согласия: backup → dry-run → создать targets → прочитать targets → удалить source последним.
8. При сбое до удаления оставить обе версии и сообщить точное состояние. При частичном удалении остановиться и использовать backup по согласованию.
9. Итог: реальные идентификаторы, N/N, post-probe, runtime log только с ids/counters.

## Gate

- [ ] Deletion test и «один сюжет» применены вместе.
- [ ] 500–1000 символов единого сюжета не режутся только из-за длины.
- [ ] Destination выбран для каждой части.
- [ ] Все target drafts готовы до мутации.
- [ ] Fact reconciliation N/N прошёл.
- [ ] План подтверждён.
- [ ] Owner override получен отдельно либо owner records не тронуты.
- [ ] Порядок create → verify → delete соблюдён.
- [ ] Post-probe проверил реальную стоимость результата.
