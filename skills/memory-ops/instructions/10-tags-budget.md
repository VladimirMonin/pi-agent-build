# Бирки проекта и бюджет инъекции 🏷️

Применяй, если запись есть в SQLite, но не появляется в контексте; контекст обрезается; один проект открыт из нескольких рабочих каталогов. Сначала прочитай [общие правила](00-shared-rules.md): пользовательские записи не переписывать без отдельного разрешения.

## Что проверять

В `@samfp/pi-memory` 1.5.0 `projectSlug(cwd)` разделяет путь только по `/`. При записи Windows-пути с `\` слагом становится **весь путь в нижнем регистре**, а не имя последней папки. Уроки с `project=<полный путь>` могут подходить такому cwd, но не такому же пути, переданному через `/`. Не назначай бирку по догадке: получи фактический cwd запуска и проверь оба написания.

В **исходном 1.5.0** факт `project.<бирка>.<тема>` проходит первичный фильтр, только когда `<бирка> === projectSlug(cwd)`; результаты поиска по смыслу и соседи добавляются *после* этого фильтра. В этой сборке version-guarded patcher проверяет все источники через нормализованный fact scope и необязательные приватные `memory.factProjectAliases`, но не меняет совместимость существующих полнопутевых бирок уроков. Простой подсчёт ключей `project.*` неверен: форматирование скрывает первый сегмент ключа. Проверяй сырые ключи на отдельной копии сборщика.

Ключи из трёх и более сегментов расширяют домен по первым двум (`a.b.*`): один подходящий факт может привести несколько длинных соседей. Двухсегментный ключ соседей не тянет. Точный предел блока версии 1.5.0 — 8000 символов; **stock** обрезает запись посреди текста, patch сборки пропускает лишние записи целиком.

## Безопасная процедура

1. Перед применением изменений создай консистентную **резервную копию** базы. Путь к БД передавай явно; не клади её в репозиторий.
2. Выполни структурную оценку: `node scripts/inject-probe.mjs --db=<COPY_DB> --estimate`. Этот публичный скрипт **не запускает плагин** и не доказывает, какой текст реально получит модель.
3. Для реального замера собери блок установленной версией плагина на **другой копии** БД и нескольких представительных парах `cwd + запрос`: корень проекта, рабочая ветка, посторонний проект, запуск без запроса. Настоящий сборщик обновляет служебные поля — не запускай его на рабочей БД ради диагностики.
4. Раздели причины: уроки с `project IS NULL`, уроки нужного cwd, попадания фактов через поиск, расширение соседей. Сравни фактический размер с 8000; при обрезании оцени полный спрос на **одноразовой копии** сборщика, не меняя установленную библиотеку ради измерения.
5. Если включаешь `memory.lessonInjection: "selective"`, перепроверь выбор **собственных уроков рабочей ветки**: stock 1.5.0 способен выбрать ноль, patch резервирует местное ядро, но при превышении бюджета и он не гарантирует полноту.
6. Перед правкой текста или бирки соблюдай owner guard и dry-run. После правки сравни результаты для всех тестовых cwd; проверь, что записи `source=user` не изменились.

Для сборки Pi исправление самого механизма относится к version-guarded patcher, а не к SQL-манипуляциям навыка. Статус и ограничения см. в репозиторном `docs/fixes/memory-injection.md`.
**Не копируй** `memory.db`, runtime-журналы или установленный `dist/index.js` в публичный репозиторий.
