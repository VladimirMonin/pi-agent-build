## How it was done

- **Разделение труда:** single-agent analysis по трём срезам источников (A/B/C) внутри
  одного саба; сама кампания велась саб-лайнами: оркестратор (mimo 2.6 xhigh) →
  исследователи (2 прямых + 4 вложенных, роль researcher) → исполнители срезов
  (worker). Приёмку срезов делали СВЕЖИЕ сабы, не авторы правок: schema smoke —
  отдельная свежая сессия (b35089c1); финальный общий контроль — саб с явным правилом
  «автор ≠ приёмщик» (cbdee70f). Авторские проверки исполнителей (verify, тесты)
  зафиксированы в их отчётах и продублированы независимыми прогонами там, где это
  критично (граф кода, транспорты).
- **Порядок работы:** разведка (коммиты → релиз-ноуты → диффы, сверка с нашими патчами,
  трудоёмкость/целесообразность) → волна анализа нашей интеграции (стыки) → план срезов
  с чек-листами приёмки → срезы 0–4, каждый: правки → установка штатными командами →
  живые прогоны → артефакт-отчёт → запись журнала → доки → коммиты/тег/заметка релиза.
- **Переработки и поучительные сбои:**
  - EBUSY на загруженном нативном модуле при живых процессах Pi оборвал npm-установку
    ядра → неполный вложенный openai уронил старт сабов («Cannot find module … turns.mjs»).
    Восстановление точечным npm-ремонтом; вывод: полная переустановка ядра — только при
    закрытых процессах Pi (журнал build.8).
  - Лаборатория шла 9/15 → 22/2 → 24/24 → 25/25. Два «красных» кейса сначала выглядели
    дефектами продукта, но сверка с источниками (build.7-заметка про exit 3, P44, §6)
    показала устаревшие ожидания тестов — правился только тест, гейты не ослаблялись.
  - Поправки к заявлениям разведки: «у intercom нет репозитория» → репозиторий найден;
    «локальные коммиты в pi-polza» → чистое отставание (таких коммитов не было).
